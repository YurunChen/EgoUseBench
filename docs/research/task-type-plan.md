# EgoCUA-Bench 新任务类型方案

更新时间：2026-08-14

## 1. 结论

主 Benchmark 保留 Graft、Refresh、Clarify 三类任务，但不再按网站类别凑满九宫格。任务是否进入核心集合，只看它是否真正依赖一段短时第一人称过程。

首轮先启用每类1道种子，再根据审核结果扩展。优先场景为：

1. 维修与兼容配件；
2. 教程与现场操作支持；
3. 地点、入口与路线；
4. 现场商品比较。

每道种子都必须让 Agent 在证据尚未完整时开始网页工作，并在后来证据到达后决定保持、追问或撤销重选。

## 2. 当前种子

当前选择：割草机教程 Graft、换刀切洋葱 Refresh、先后两张海报 Clarify。三道题的连续视频、抽帧、网站实体、标准答案和模型输入预审已经跑通；尚未完成两名独立审核者的 Glass-Use 必要性审核，因此都只是种子候选。

## 3. 其余103条来源记录为什么不生成任务

来源池共有106条记录，只有3条由 `data/selection.json` 选中并编译。其余103条不进入人工审核和正式实验。它们可以继续提供原始视频、对象线索和网页场景，但必须从连续视频重新证明 Glass-Use 必要性，不能只改指令重新包装。

## 4. 通用任务合同

所有任务按同一条链路设计：

```text
连续视频中的现实事件
→ Agent 按时间获得的画面
→ 必须做出的等待、追问、保持或修正决定
→ 网页状态变化
→ 确定性完成条件
```

任务开始前先写清楚：

- 哪一刻之前证据不足；
- 哪一刻之后能够唯一判断；
- Agent 在等待期间可以安全做什么；
- 哪个动作属于过早承诺；
- 新证据到达后是否需要撤销已有选择；
- 最终网页状态是什么。

## 5. 场景设计

### 5.1 维修与兼容配件

**自然过程**

用户双手正在拆装设备。开始只看到零件外形，翻转、拆开或拔出后才露出接口、规格标签或连接方式。

**网页过程**

```text
根据外形搜索部件类别
→ 比较多个兼容候选
→ 等待接口或型号证据
→ 选择唯一兼容项
→ 必要时移除错误临时项
→ 提交
```

**有效难点**

- 接口出现前加入具体配件属于过早承诺；
- 后来规格与原判断冲突时必须撤销；
- 标签仍看不清时应询问一个最小问题。

**数据来源**

优先从 HD-EPIC 的对象移动、工具使用和设备拆装片段，以及 Ego2Web 的工具、设备和配件视频中筛选。

### 5.2 教程与现场操作支持

**自然过程**

用户正在安装、维修、烹饪或制作。Agent 需要根据已经完成的动作和当前卡住的步骤选择教程，而不是只根据物体类别搜索通用内容。

**网页过程**

```text
搜索设备或操作类别
→ 打开教程候选
→ 随用户操作确认当前阶段
→ 核对字幕或步骤
→ 保存覆盖正确阶段的内容
→ 提交
```

**有效难点**

- 只看最终物体不能恢复用户当前处于哪个步骤；
- 教程必须覆盖当前问题和下一步，而不只是标题相似；
- 用户完成一步后，旧教程或旧章节可能不再合适。

**数据来源**

优先筛选 Ego2Web 的安装、拆卸、烹饪和手工操作视频。原始任务文字只用于发现候选，最终语义必须由连续视频确认。

### 5.3 地点、入口与路线

**自然过程**

用户在步行过程中先看到建筑或远处招牌，接近后才看到具体入口、街道方向、停车点或无障碍信息。

**网页过程**

```text
定位地点
→ 查看候选分店或建筑
→ 等待入口证据
→ 选择具体入口和路线方式
→ 添加必要途经点
→ 提交
```

**有效难点**

- 地点可先定位，具体入口不能提前确定；
- 后来出现另一个入口时，需要根据用户行动判断保持还是修正；
- 两个入口仍然合理时，应先询问。

**数据来源**

从 Ego2Web 的31条地图任务和21段不同视频中重新筛选。只有连续行走过程能支持远景到入口变化的片段才进入构造。

### 5.4 现场商品比较

**自然过程**

用户在货架或桌面前拿起、翻转、比较并放回商品。包装背面、容量、接口或最终放入篮子的对象在后续画面中出现。

**网页过程**

```text
按类别或品牌搜索
→ 比较网页版本
→ 等待背面或最终选择证据
→ 选择正确版本
→ 撤销错误项
→ 提交
```

**有效难点**

- 商品正面不足以区分容量或版本；
- 拿起不等于最终选择，放回和最终保留必须在视频中可见；
- 评分、价格等纯网页条件只能增加网页比较难度，不能单独构成 Glass-Use 难点。

**数据来源**

Ego2Web 用于商品、品牌和网页任务映射；HD-EPIC 用于连续拿取、翻转、放回和替换事件。两个来源的事实不能未经证据直接拼接成一次真实事件。

## 5. 三类交互如何保留

Graft、Refresh、Clarify 不再要求每个网页场景各做一道。

- **Graft / Integrate**：只有当补充要求发生在用户仍在进行的现实操作中，并影响当前网页选择时才保留；普通“再加一个评分条件”不保留。
- **Refresh / Retain / Revise**：作为核心视觉决定，必须由连续视频证明后续证据应保持或改变目标。
- **Clarify**：作为 Agent 动作，只有在当前发布证据仍不足、且一个问题能唯一确定目标时才使用。

每道任务只注册一个主要决定。其他行为可以自然发生，但不同时宣称测量多个独立能力。

## 6. 首轮种子选择

先从已有来源中寻找下面三道，不要求凑齐后才保留：

1. **维修配件 Revise**：后续接口或标签推翻早期候选；
2. **现场操作 Clarify**：到决策点仍有两个合理部件或步骤；
3. **入口路线 Retain / Revise**：接近建筑后出现决定性入口证据。

若来源不足，再加入：

4. 教程阶段选择；
5. 商品背面规格选择；
6. 用户操作中的自然补充要求。

没有合格连续证据时，种子数可以少于3，不使用生成画面或虚构事件补齐。

## 7. 人工审核

审核者直接判断下面五件事：

1. 这是不是一次合理的短时眼镜任务；
2. 开始画面是否确实不足；
3. 后续画面是否提供了新的决定性证据；
4. 静态截图是否不能等价替代；
5. 网页中的正确结果是否唯一且可执行。

五项全部通过后，才继续做真实网站执行、checker 反例和模型运行。审核者不再填写与任务理解无关的工程字段。

## 8. 完成标准

一条种子达到 `approved` 前必须完成：

- 连续视频和发布时间线由两名审核者同意；
- 两名独立人类完成正式任务；
- 过早提交、错误保持、错误更新、额外实体和无效提问都能被检查器拒绝；
- 至少一次 GPT-5.4-mini + Browser-Use 协议有效运行；
- 任务、画面、站点和 evaluator 哈希冻结。

模型失败不淘汰任务，模型成功也不能代替构念审核。
