# EgoCUA-Bench 设计说明

## 1. 研究问题

智能眼镜的价值不只是提供一张第一人称图片，而是让用户在双手被占用、仍在移动或操作物体时，也能持续完成现实到网页的任务。

EgoCUA-Bench 研究：

> 在一次用户主动开启的短时第一人称会话中，现实证据尚未完整并继续变化时，网页智能体能否避免过早承诺，并在正确时机等待、追问、保持选择或撤销重选？

这里的“承诺”指会改变候选状态的网页动作，例如加入购物车、保存教程、选定入口或提交路线。搜索、浏览和比较可以提前进行；在证据不足时选定具体目标属于过早承诺。

本项目不研究全天录像、后台环境监控或自主发现生活事件。消费级眼镜可以长期佩戴，但视觉 Agent 由用户主动唤起，只在当前任务会话内获取画面。

## 2. 为什么不是普通的手机或电脑任务

如果一项任务只需要上传一张照片，再在网页中搜索商品，那么手机、电脑和眼镜的输入没有本质区别，这类任务不进入核心集合。

核心任务必须依赖下面的过程：

```text
用户开始任务时只出现部分证据
→ 用户继续拿取、翻转、安装、比较或行走
→ Agent 同时进行不依赖最终身份的网页搜索
→ 后续第一人称证据自然出现
→ Agent 决定继续等待、主动确认、保持原判断或撤销重选
```

眼镜在这里提供的是免手持、第一人称和任务期间持续可用的视觉入口。手机理论上也能开启视频，但需要用户持握、对准和切换应用；Benchmark 测量的是这类任务级可穿戴交互，而不是声称手机绝对无法完成。

正式研究还应在少量代表任务上报告“仅任务开始截图”的输入消融。如果截图输入与短时顺序输入表现相同，说明该任务没有形成 Glass-Use 难点。

## 3. 统一任务过程

每道正式任务只有一个自然执行过程：

1. 用户通过语音或按键启动任务；
2. Agent 收到当前第一人称画面和初始要求；
3. 用户继续现实活动，Agent 可以同步进行搜索和浏览；
4. 后续画面或用户信息按来源时间顺序到达；
5. Agent 选择等待、提问、继续原计划或撤销已有选择；
6. Agent 完成网页提交；
7. 视觉会话结束。

关键帧是短时连续视频的模型输入表示，不是用户手动拍摄的多张照片。来源视频怎样录制，不等于产品怎样交互；发布画面必须对应一次合理的任务级会话。

首版继续使用预先抽取的图片，不直接传输视频和音频。新画面或补充要求在第2个交互回合开始时送达，不再由“首次出现搜索结果”决定。这个固定回合只用于可复现地模拟任务时间线，不随搜索内容或搜索是否成功而变化。

## 4. 三类任务

Graft、Refresh 和 Clarify 是基准的三条主轨。统一的研究动机是短时眼镜任务会话；三条轨道分别定位信息从哪里发生变化。每道任务只属于一条轨道。

| 轨道 | 现实情况 | 正确行为 |
|---|---|---|
| Graft | 用户在操作过程中补充与当前物体有关的要求 | 保留仍有效部分，并调整网页选择 |
| Refresh | 后续视觉证据不改变或改变现实所指 | 抵抗无关变化，或撤销旧目标后重选 |
| Clarify | 当前画面与说法仍对应多个合理候选 | 在首次候选承诺前提出最少且有效的问题 |

静态画面加一条网页筛选条件不是有效 Integrate；两张不同图片也不能自动证明 Revise。任务必须由连续视频支持用户动作、对象变化和先后关系。

## 5. 任务准入标准

每道任务必须通过以下检查：

### 5.1 Glass-Use 必要性

- 开始画面不足以安全确定最终网页目标；
- 后续证据来自同一段合理的短时第一人称会话；
- 用户在会话中仍在操作物体、移动或观察环境；
- 静态截图和完整文字不能等价替代这段过程；
- Agent 在证据到齐前至少有一项可做但不应提交的网页工作。

### 5.2 来源有效性

- 连续视频明确显示对象、动作和先后关系；
- 目标粒度不超过画面真正支持的类别、品牌、变体或实例；
- 不根据单帧、文件名或原任务文字补写视频中没有发生的事件；
- 不用生成图片制造现实变化；
- 若用户后续语句不是来源视频中的自然语音，明确标为 Benchmark 编写，不能声称来自真实对话。

### 5.3 网页必要性

- 必须搜索、比较、配置或修改网页状态；
- 最终结果不是一句事实答案；
- 新证据会改变正确网页操作或正确提交时机；
- 目标和干扰项都能通过真实页面字段区分；
- 最终状态由实体ID、字段和提交状态确定检查。

### 5.4 直接拒绝

出现下面任一情况，任务不进入核心集合：

- 只看任务开始截图即可完成；
- 后续条件只是价格、评分、时长等普通网页筛选；
- 完整视频在任务开始时一次性提供，Agent 不需要在线等待或更新；
- 后续视觉按网页搜索进度凭空出现；
- 任务靠增加无关点击制造难度；
- 来源无法证明目标替换、目标保持或视觉歧义。

## 6. 优先场景

首轮不按网站、轨道或预设数量凑题。所有候选逐题通过 Glass-Use 必要性和证据门禁，符合多少保留多少。

### 6.1 维修与兼容配件

用户正在拆装设备，开始只能看到外观，翻转或拆开后才出现接口、尺寸、型号或电压。Agent 可以先搜索部件类别，但在决定具体配件前必须等待后续证据，必要时询问用户。

网页结果：选择唯一兼容配件，移除早先错误项并提交。

### 6.2 教程与操作支持

用户双手正在进行安装、烹饪或维修。不同操作阶段对应不同教程或不同章节；Agent 需要根据用户已经完成和当前卡住的步骤选择正确内容，而不是只根据物体类别搜索通用教程。

网页结果：保存覆盖正确设备、当前步骤和后续动作的内容并提交。

### 6.3 地点、入口与路线

用户正在步行，开始只能看到建筑或招牌，接近后才出现具体入口、方向或无障碍信息。Agent 可以先定位地点，但不能在入口证据出现前提交具体路线。

网页结果：选择正确地点、入口、路线方式和必要途经点。

### 6.4 现场商品比较

用户在货架前持续比较、拿起和放回商品。只有当包装背面、容量、接口或最终放入篮子的对象出现后，才能确定网页目标。只展示商品正面并要求搜索同款不属于本类。

网页结果：选择最终对象对应的正确版本，并撤销已不符合的临时选择。

## 7. Agent 输入与动作

每一步 Observation 包含：

- 当前网页截图和可交互元素；
- 到当前时刻已经释放的第一人称画面；
- 已经发生的用户语句或澄清回答；
- 当前任务是否仍在等待后续现实证据。

网页动作沿用：

```text
search
open_entity
select_entity
deselect_entity
set_field
submit
```

交互动作需要支持：

```text
wait
ask_user
```

`wait` 消耗一步并推进任务时间线；它不是失败，也不能无限使用。`ask_user` 只在剩余视觉证据仍不足以唯一确定目标时有效。第一版最多允许一次问题。

## 8. 网站与最终状态

继续保留三个确定性本地站点：

| 网站 | 工作流 | 唯一数据源 |
|---|---|---|
| EgoMart | 搜索、比较、配置、购物车、提交 | `sites/egomart/products.json` |
| EgoMedia | 搜索、查看步骤、保存、填写字段、提交 | `sites/egomedia/videos.json` |
| EgoMaps | 搜索地点、选择入口和路线、提交 | `sites/egomaps/places.json` |

统一最终状态为：

```json
{
  "selected_entity_ids": ["..."],
  "fields": {"...": "..."},
  "submission_completed": true
}
```

每次运行从冻结站点数据创建新的内存状态，任务之间确定性重置。网站内容是网页真值的唯一来源，任务文件不复制商品、教程或地点文本。

## 9. 评估

一次 E2E 成功要求最终实体、字段和提交状态完全正确，没有额外、遗漏或重复结果，并且所有必需现实事件在提交前已经到达。

核心诊断指标：

- **Premature Commitment Rate**：关键证据到达前选择或提交具体候选的比例；
- **Stale Commitment Rate**：新证据已经推翻旧目标后仍保留旧选择的比例；
- **False Update Rate**：无关变化出现后错误切换目标的比例；
- **Clarification Precision**：提问发生在确有必要的任务中的比例；
- **Clarification Timing**：是否在首次候选承诺之前提问；
- **Revision Success**：错误或临时选择能否被正确撤销；
- **Productive Progress**：证据未齐时是否完成了不会锁定错误目标的搜索和比较；
- E2E Success、总步骤数、等待步数、重复动作率。

少量代表题另做“任务开始截图”输入消融，用于证明顺序视觉输入的必要性。它是分析设置，不复制任务，也不出现在默认人工审核中。

## 10. 构建与发布门禁

构建顺序固定为：

```text
连续来源视频
→ 发布时间线
→ 必需决定
→ 网页状态变化
→ 确定性谓词
```

每道任务依次通过：

1. 两名审核者确认连续视频和 Glass-Use 必要性；
2. 检查静态截图不能等价完成任务；
3. 两名独立人类通过正式输入完成任务；
4. 检查器拒绝过早提交、错误实体、额外实体、错漏字段和无效澄清；
5. GPT-5.4-mini + Browser-Use 至少产生一次协议有效运行；
6. 冻结任务、视觉输入、网站、检查器和配置哈希。

模型成功不决定任务是否入选。来源视频簇在主分析中最多贡献一道任务。

## 11. 当前审核队列与筛选记录

当前审核队列只由 `data/selection.json` 定义。Source manifest 保存每条来源的筛选证据和淘汰原因，其记录总数不是 Benchmark 规模。进入 selection 只表示任务已编译且机器一致性检查通过，不表示 Glass-Use 必要性已通过人工审核。

当前任务 ID 和分轨数量以 `data/selection.json` 为准，机器验收状态以 `artifacts/reports/task-acceptance.json` 为准，正式发布状态以 `data/releases/` 为准。当前仍无正式发布任务。
