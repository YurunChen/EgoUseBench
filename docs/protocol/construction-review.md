# 任务构造审核

程序可以检查文件、实体 ID 和判分逻辑，但不能代替人判断画面是否清楚、指令是否自然、任务是否公平。因此，每道候选任务需要两名审核者独立确认。

## 开始审核

每名审核者使用自己的名字启动本地网站：

```bash
uv run egocua review --reviewer reviewer-a
```

网站只绑定本机，并自动打开浏览器。审核者不需要查看或填写 JSON。

## 审核顺序

1. 查看本题的用户指令、动态过程和 Agent 实际接收的连续抽帧。
2. 查看“现实场景依据”，确认对象、动作和先后关系能回到具体画面，并区分视频中真实发生的变化与基于真实画面编写的用户补充。
3. 查看基准答案，包括最终目标、必要字段和提交状态。
4. 对照来源记录、目标、干扰项和冻结网站，判断任务与答案是否成立。
5. 页面列出需要留意的核对重点，但不要求逐项作答。
6. 整体没有问题时直接保留；发现问题时写一句说明并提交。审核者不需要重新做题或填写问卷。

全部必要检查通过且没有未解决问题时，系统将该次审核记为“保留”；其他情况记为“淘汰”。

## 独立性

- 两名审核者分别启动自己的审核会话。
- 页面只显示当前审核者的进度和结果。
- 提交后不能覆盖原结果。
- 模型预审不能代替人工审核。
- 两人意见不同、目标粒度不同或任何一项未通过时，任务淘汰。

这套机制提供流程隔离，不提供操作系统级保密。正式审核时，两名审核者不应直接查看 `data/reviews/submissions/` 中对方的文件。

## 单一真相源

- `data/selection.json` 决定当前需要审核的候选任务。
- `data/reviews/construction.json` 只保存统一审核问题和双人审核规则。
- 任务、抽帧、来源记录和网站内容从各自当前真值源读取。
- 个人结果保存在 `data/reviews/submissions/<task-id>/<reviewer>.json`。
- 审核进度实时计算，不保存独立进度表。

任务、图片、来源、网站数据或审核规则发生变化后，旧页面不能继续提交，已有审核会被标为需要重审。

## 汇总检查

```bash
uv run python -m tools.audit_construction_reviews --root .
```

只有两名审核者都保留的任务才能生成下一阶段的构造证据：

```bash
uv run python -m tools.promote_construction_reviews --root .
```
